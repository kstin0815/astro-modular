# 臉書同步說明

這份是同步流程的完整規格：Claude 每次同步都照這份做；規則要改，就改這份。`_sync` 資料夾不會出現在網站上。

## 檔案在哪裡

| 位置 | 內容 |
| --- | --- |
| `docs/分類/YYMMDD.md` | 一篇臉書貼文（放在 Docs，因為都還是未完成的素材）。檔名＝發文日期碼，同一天第二篇用 `YYMMDD-2`。所在資料夾就是分類。 |
| `docs/attachments/YYMMDD-n.jpg` | 貼文的圖片（所有分類共用一個資料夾，換分類時圖片不受影響）。 |
| `_sync/共用區塊/代號.md` | 共用區塊（見下方「區塊類型」）。 |
| `_sync/貼文索引.md` | 所有出現過的貼文：臉書編號、標題、日期碼、舊標題；已收錄的還有「內文指紋」「留言指紋」（記錄目前臉書上的版本，用來發現改動、判斷哪些留言要更新）和「最後檢查」日期。還沒收錄的文章只能靠這裡把標題對回臉書網址。 |
| `_sync/洞察總表.base` | 在 Obsidian 打開，把所有文章的臉書洞察數字列成一張表（可排序、篩選）。 |
| `_sync/待貼留言.md` | 需要更新的臉書留言，每則一個程式碼區塊，可直接複製；上方列出這次新增、刪除、移動、改標題了什麼。 |
| `_sync/留言原文/檔名.txt` | 臉書上目前那則整理留言的原文（收錄時、或我貼好後記下），用來比對待貼留言改了什麼。 |
| `scripts/fbsync.py` | 輔助程式。 |

## 一篇文章長這樣

```

title: "▌再過幾天(10/31)就是台北市長電視辯論。"

date: 2026-10-25
category: "辯論"        # 自動等於所在資料夾，不用手改
```

### 內文
- 標題保留臉書的樣子（含 ▌），只放在 `title`，內文不重複。
- 刪除臉書的零寬空白。
- `--` 保留兩個減號，照原樣顯示。
- 單獨一行的 `#小標` 用程式碼包住成 `` `#小標` ``（不轉成網站小標題）。
- 其他照原文，換行照原樣。

### 分類（資料夾）
- 分類就是 `docs` 底下的資料夾，名稱一律兩個字：`辯論`、`表達`、`觀點`、`閱讀`、`生活`（之後可能加 `寫作`、`思考`）。
- 換分類：在 Obsidian 把檔案拖到另一個資料夾，再執行 `sync`，`category` 會自動更新。網站網址會跟著變（`/docs/分類/YYMMDD`），但 wikilink 和「提到這篇的文章」都用檔名比對，不受影響。
- 收錄新貼文時，Claude 依內容直接決定分類（不用問我），回報時說明放在哪裡；放錯我再拖曳檔案換。

### 圖片
- 貼文有圖片就直接下載（我已同意，不用再問）：在瀏覽器用 fetch 取得圖片後存到「下載」資料夾，檔名 `fbsync-YYMMDD-n.jpg`（工作區無法直接連到臉書圖片伺服器）。
- 收錄時加 `--images 圖1 圖2…`：存成 `docs/attachments/YYMMDD-1.jpg`…，依序放在內文最後（和臉書一樣在文字下方）。
- 第一張圖同時設為 `image`（分享連結的預覽圖），並加 `hideCoverImage: true`，所以不會在文章頁上方或 Docs 清單卡片顯示。沒有圖片就沒有這兩個欄位。
- 網站建置時會自動轉成 WebP。重新收錄（例如內文修改）時，原本的圖片會保留。

### 舊文重發（原文日期）
- 內文第二行若是 `［原文寫於：2022-01-01 18:35］`，檔名和日期碼一律用原文日期（例如 `220101`），和留言裡的日期碼一致。
- 臉書發文日期另外記在 `fbDate`。這一行照原樣保留在內文開頭。

### description（網站摘要）
取第一個一般段落（跳過 `#小標`、`--`、• 開頭的行），去掉開頭編號（⒈、1.）。80 字以內整段使用；超過就在 80 字內最後一個「。？！」截斷；找不到就取前 78 字加「…」。

### 相關文章
- 跟臉書整理留言一樣：一行一篇，區塊之間用 `--`，標籤自成一行（`#辯論` 這類用程式碼包住，`01` 這類照原樣），只是不放網址。
- 第一個區塊是前後篇：第一行是本篇自己，其後是我在留言裡寫的相關前作。不會自動雙向加入；收錄新貼文時 Claude 會詢問是否要把新貼文加到被引用文章的第一區塊。
- 已收錄的文章寫成 `[[檔名|標題]]日期碼`；還沒收錄的只寫標題和日期碼，不放連結，收錄後自動改成連結。
- 別人的貼文或外部網址保留成 `[文字](網址)`。
- 共用區塊寫成 `![[代號]]`：Obsidian 會直接顯示內容，網站上展開成一般的行。

### 臉書留言
- 貼回臉書的版本：每篇（標題＋網址）之間空一行，`--` 前後各空一行。網站備份不空行。
- 待貼留言每則都要先列出改了什麼（新增、刪除、移動到哪個區塊、標題修正、補上日期），回報時也照列，不能只給整則留言。
- 標題後一律加日期碼（不知道日期的文章暫時不加，收錄後或在貼文索引補上日期就會出現）。
- `#辯論` 這類標籤在臉書上照原樣（不加程式碼符號）。
- 留言裡每一篇都已經有日期碼時，只要和臉書上目前的留言不同（新增文章、共用區塊更新、標題修正、格式修正，或臉書上缺日期要補上），就列進 `待貼留言.md`。還有文章缺日期的先不更新，等日期補齊後再一起更新。

## 區塊類型

區塊都放在 `_sync/共用區塊/`，檔名是代號，不用中文名稱。代號的第一個字母是類型：

| 代號 | 類型 | 說明 |
| --- | --- | --- |
| `L01`… | 清單 | 沒有名稱、之後可能會增減的一組文章：相關主題，或還不確定怎麼整理的組合。 |
| `S01`… | 系列 | 已完成、有固定順序的系列。內容不再變動。 |
| `T01`… | 主題 | 明確同一類的文章整理。之後可以在網站上有自己的頁面。 |
| `A01`… | AI 精選 | 給 AI 讀的代表作。不會出現在留言或文章裡；每行後面可以加「｜選入理由」。之後再做匯出。 |

- 檔案內容就是一行一篇（寫法同相關文章）。系列、主題、AI 精選可以在檔頭（frontmatter）加 `說明:`（只給自己看）。
- AI 精選的寫法：用 `#標籤` 分組、組之間用 `--` 隔開；每行「文章｜選入理由」，理由一句話。整組已經是共用區塊的，直接寫 `![[代號]]｜理由`。
- 建立 AI 精選之前，先把其他文章留言裡已經重複出現的組合建成共用區塊。
- 一篇文章自己所屬的清單，在它自己的留言裡會少了它自己，所以不會被換成區塊，照原樣列出。
- 清單：檢查時若發現同一組三篇以上出現在兩則以上留言，會建議建立新的清單。
- 新增區塊檔案後執行 `sync`，所有文章裡相同的組合會自動換成這個區塊（臉書留言內容不變）。

## 同步一篇（「同步這篇＋網址」）

1. 用內建瀏覽器開貼文（已登入；只讀取，不按讚、不留言）。在含「分享對象」的對話框取文字：內文在「分享對象：所有人」之後、「查看洞察報告」之前，第一行是標題。去掉零寬空白後在瀏覽器算 SHA-256，存檔後用 `printf '%s' "$(cat 檔)" | sha256sum` 比對，必須一致。
2. 整理留言：對話框裡以「張子龍」開頭、含 facebook.com 連結的那則，去掉開頭的名字時間與結尾的「回覆／已編輯」。發文日期：放大貼文標頭的「X月X日」。
3. 執行 `python3 scripts/fbsync.py import --fb 編號 --date YYMMDD --folder 分類 --post 內文.txt --comment 留言.txt [--images 圖…]`（建立或更新文章、貼文索引（含留言指紋），並同步所有文章）。只有印出「要不要在這些文章的第一區塊加上本篇？」時才問我（不自動加）。
4. 執行 `python3 scripts/fbsync.py check`，回報：需要更新的臉書留言（已寫進 `待貼留言.md`）、收錄後要補上的舊文、貼文索引待確認的項目（請我決定；決定後備註寫「已確認」）、建議建立的清單。
5. 依下方「抓出改過的舊文」檢查舊文，有改動的一併重新收錄。
6. 新貼文和這次檢查過的舊文，都依下方「洞察數字」更新文章屬性裡的數字。
7. 我貼好留言後，執行 `python3 scripts/fbsync.py mark-posted 檔名…`（更新貼文索引的留言指紋）。
8. 不建立分支、不提交、不推送；我用 `pnpm dev`（http://localhost:5000）預覽，確認後自己用 Obsidian Git 同步。不在網站資料夾執行 `pnpm install`；要測試建置就複製到工作區再做。

## 抓出改過的舊文

我常在寫新文時順手修改舊文，而且自己不會記得。所以每次同步時，除了新貼文，還要檢查：
1. 新貼文整理留言裡引用到的、已收錄的文章（寫新文時最可能看過、改過的那幾篇）。
2. 再加上 `python3 scripts/fbsync.py due 5` 列出的「最久沒檢查」的 5 篇，輪流把所有文章都檢查到。

檢查方法：在瀏覽器開那篇，算內文的 SHA-256（去掉零寬空白），前 10 碼和貼文索引的「內文指紋」比；也讀整理留言，比對「留言指紋」（存成暫存檔後用 `fbsync` 的 `fingerprint` 計算）。都沒變就執行 `checked 檔名`；有變就照「同步一篇」重新收錄。
我也可以說「全部檢查一次」，就把所有已收錄文章照這個方法檢查一遍。

## 洞察數字

臉書洞察報告的數字存在各篇文章的屬性（frontmatter）裡，只留最新一次（變化臉書自己有圖），不會出現在網站上。欄位：

`洞察日期`、`瀏覽次數`、`瀏覽者`、`追蹤者瀏覽`、`非追蹤者瀏覽`、`心情`、`留言`、`點擊`、`分享`、`收益`（美元）、`第1天瀏覽`、`第3天瀏覽`、`第7天瀏覽`、`第14天瀏覽`（從「長期瀏覽次數」圖讀出的累計瀏覽，是近似值；臉書這張圖只畫前 21 天，終點和總瀏覽對不上是臉書本來就這樣）。不記新追蹤、年齡、國家。

做法：在貼文頁點「查看洞察報告」（只讀取），在洞察頁執行下面的程式，再執行 `python3 scripts/fbsync.py metrics 檔名 '程式回傳的 JSON'`。重新收錄文章時這些數字會保留。

```js

const L=box.innerText.split('\n').map(s=>s.replace(/\ufeff/g,'').trim()).filter(Boolean);
const isNum=s=>/^\$?[\d,]+(\.\d+)?%?$/.test(s), num=s=>s==null?'':s.replace(/[,$]/g,'');
const before=lab=>{const k=L.indexOf(lab);return k>0&&isNum(L[k-1])?num(L[k-1]):''};
const nextNum=lab=>{const k=L.indexOf(lab);if(k<0)return '';for(let j=k+1;j<L.length;j++){if(isNum(L[j])&&!L[j].endsWith('%'))return num(L[j]);}return ''};
const rev=L.find(s=>/^\$[\d.]+收益約略值$/.test(s));
// 長期瀏覽次數圖：依座標軸換算累計瀏覽
const svg=[...document.querySelectorAll('svg')].find(s=>/^\d+天/.test(s.textContent)||s.textContent.includes('5天'));
let curve={};
if(svg){const tr=t=>t.parentNode.getAttribute('transform');
 const tx=[...svg.querySelectorAll('text')].filter(t=>/天$/.test(t.textContent)).map(t=>({d:parseInt(t.textContent),x:+tr(t).match(/translate\(([\d.]+)/)[1]}));
 const ty=[...svg.querySelectorAll('text')].filter(t=>/^[\d,]+$/.test(t.textContent)).map(t=>({v:+t.textContent.replace(/,/g,''),y:+tr(t).match(/,\s*([\d.]+)/)[1]}));
 const ppd=(tx[1].x-tx[0].x)/(tx[1].d-tx[0].d), x0=tx[0].x-tx[0].d*ppd, vpp=(ty[1].v-ty[0].v)/(ty[0].y-ty[1].y), y0=ty[0].y+ty[0].v/vpp;
 const line=[...svg.querySelectorAll('path')].find(p=>(p.getAttribute('d')||'').length>500&&getComputedStyle(p).fill==='none');
 const pts=[...line.getAttribute('d').matchAll(/[ML]([\d.]+),([\d.]+)/g)].map(m=>[(+m[1]-x0)/ppd,(y0-+m[2])*vpp]);
 const at=d=>{let b=null;for(const q of pts){if(q[0]<=d+1e-6)b=q;}return b&&pts[pts.length-1][0]>=d-0.1?Math.round(b[1]):''};
 curve={第1天瀏覽:at(1),第3天瀏覽:at(3),第7天瀏覽:at(7),第14天瀏覽:at(14)};}

 追蹤者瀏覽:before('追蹤者'), 非追蹤者瀏覽:before('非追蹤者'), 收益:rev?num(rev.replace('收益約略值','')):'', ...curve})
```

讀到的數字要合理（第 N 天瀏覽應遞增、且不超過總瀏覽）；臉書改版導致讀不到時，先停下來告訴我，不要記錄錯的數字。發文不到 14 天的文章，還沒到的天數會留空，下次檢查再補。

分析：在 Obsidian 打開 `_sync/洞察總表.base`；或執行 `python3 scripts/fbsync.py export` 產生 `_sync/洞察匯出.csv`（需要時才產生，可用 Excel 打開）。

## 其他

- 貼文索引備註寫「已確認」的標題，重新收錄時保留（臉書第一行若不同，列為舊標題）。例如 260409 用〈2026淡江建言社課講座：申論的架構。〉。
- 改標題：已收錄的文章以文章本身為準，重新收錄就會更新；未收錄的直接改貼文索引，舊標題移到「舊標題」欄，再執行 `sync`。
- 改區塊內容：直接編輯 `_sync/共用區塊/代號.md`，再執行 `sync`。
